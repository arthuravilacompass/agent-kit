- **`check-provenance.sh` stops shipping the confidential literals it exists to ban — denylist split into structural (shipped) vs. literal (local, gitignored) tiers, operator decision (2026-07-28)** — this repo is public, and the gate's `DENY` variable held every client/engagement literal it was written to catch, in plain sight, in a tracked file — including a comment block that didn't just contain the tokens but *labeled* them ("the origin's real client name", "the origin's real internal package name"), narrating the identity it was supposed to be hiding right next to the pattern that hunts for it. The file meant to protect confidentiality was the one publishing it. Compounding cause: the gate excludes itself from its own scan (`git ls-files -z ':!:scripts/check-provenance.sh'`) out of necessity — a file can't grep-ban its own contents — which is exactly the gap that let the literals sit there unflagged.

  **The split, and the criterion behind it.** Patterns that are ticket-ID or branch-naming *formats* (a Jira-style prefix, a release-branch year suffix) identify nobody — a format is safe to publish — and stay hardcoded in the script. Patterns that are actual proper nouns (a client name, an internal domain, a squad name, a CI vendor tied to this engagement, personal handles) went to a new `.provenance-deny` at repo root: gitignored, one `grep -E` alternative per line, `#` comments, blank lines ignored. `.provenance-deny.example` ships tracked, with placeholder values only, documenting the format and the absence behavior below so the mechanism is self-explanatory to anyone who clones the repo fresh. One case-sensitive, word-bounded discriminator from the old comment block is worth keeping as doctrine even with the literal gone: a proper noun can happen to spell an ordinary word of the kit's own working language, capitalized — an unbounded or case-insensitive match on it would false-positive against the kit's own legitimate lowercase vocabulary. That reasoning is now stated generically in the script; the literal it protects lives only in the gitignored file.

  **The clone-without-the-file question, decided empirically rather than by intuition.** `scripts/` isn't part of any plugin manifest — this gate never ships to a plugin installer. It runs in exactly two places: the maintainer's local pre-commit gate, and `.github/workflows/ci.yml` on every push/PR. CI's own checkout **never** has `.provenance-deny` — gitignored means never pushed — which makes "clone without the local file" the gate's guaranteed, recurring real state, not a hypothetical. Failing hard on absence would turn the maintainer's own CI permanently red on every run, which is worse than the exposure it would guard against. So: absence runs the gate with structural patterns only, and is never silent about it — the `OK`/`FAILED` line always states how many local literal patterns loaded, `0` when the file is missing, so losing the file shows up in the gate's own output on the very next run rather than as nothing at all. A file that *exists* but yields zero usable lines (all blank/comment) is treated differently — exit 2, indeterminate — the same doctrine the script already applied to an empty tracked-file set: content that should be there but silently isn't is a suspect state, not a clean one, and truncation shouldn't read as "nothing to hide."

  **Validated, not just written.** An isolated throwaway git repo (outside this tree) carrying only the refactored script and a `.provenance-deny` copy confirmed the composed pattern catches the two real cases and spares the two legitimate lowercase look-alikes it's designed around, in the same fixture — plus separately confirmed the gate still passes clean, structural-only, with the file absent, and returns the new indeterminate exit code when the file is present but empty of usable patterns. Against the real tree: `git check-ignore -v .provenance-deny` confirms it's ignored (and absent from `git status --short` entirely, which is the ignore proof); the gate is green with the file present and green (structural-only) with it removed and restored; a targeted `git grep` for the two literals named in the old comment block, excluding the script and the local file, returns zero hits. `docs/OPERATIONS.md` §4 documents the split and the clone-without-file behavior; §1's placeholder warning updated to note the literal tier is a local, pre-commit check, not something CI alone enforces. No plugin version bump — same precedent as the other `scripts/`-only entries in this file: this script isn't part of any plugin manifest. **The lesson, stated for reuse**: a denylist of confidential terms cannot live in tracked content in a public repo, full stop — and a gate that has to exclude itself from its own scan to avoid self-matching is not an implementation detail, it's the symptom that the denylist itself doesn't belong where it's sitting.

- **Hook timeouts, and a retirement marker on the three gates whose subject is a model behavior (2026-07-27; core 0.23.0→0.24.0)** — two small shipped-behavior changes that share a theme: bounding what a gate can cost, in wall-clock and in relevance.

  **Timeouts.** Every entry in `plugins/core/hooks/hooks.json` was inheriting Claude Code's 600-second default, so a hook that hangs holds the turn for ten minutes. Each of `core`'s five hook entries now declares a `timeout` in its command object: `read-ledger.sh` and `model-routing.sh` and `no-silent-removal.sh` at **10s**, `session-start.sh` at **30s**, `citation-check.sh` at **45s** — the last one higher on purpose, because it shells out to `validate_citations.py` under `subprocess.run(..., timeout=30)`, and a hook bound at or below its own child's would cut the check off before the child could return a verdict. The measured typicals these bounds sit far above: `read-ledger.sh` 103ms over 429 recorded runs, `model-routing.sh` 232ms, `session-start.sh` 190ms. The `timeout` field's behavior was verified empirically by the maintainer before this change, not read off documentation: a hook sleeping 30s under `"timeout": 3` was cut short and the turn survived. **The motivating incident, stated with the limit of what it shows**: a `PreToolUse:Edit` run of `model-routing.sh` was recorded at `durationMs: 901172` with `timedOut: true` against `timeoutMs: 600000`, and it blocked an edit. Note that the recorded duration *exceeds* the timeout it was measured against — which points at wall-clock elapsing during system sleep rather than at a live hang, so this change bounds the damage without claiming a root cause for it. **Out of scope, named as follow-up**: `plugins/mobile/hooks/` still inherits the default on every entry.

  **`# retire-review:` markers.** The kit governs an artifact's kind, its state (wired/unwired/deleted) and its size (the always-on ratchet), but it has no surface for *trajectory* — and a gate whose subject is a **model behavior** depreciates in relevance as models improve while remaining mechanically correct the whole way down. Worse for a blocking gate than for prose: stale prose is dead weight, a stale block is a false positive, which this branch demonstrated on itself when the mis-scoped citation hook hard-blocked ESLint's output at exit 2. Three hooks are in that class and each now carries a `# retire-review:` line on line 3, directly beside its `# desc:`: `model-routing.sh` (a synthesis-tier session model writing a code artifact itself instead of dispatching it), `no-silent-removal.sh` (an edit dropping a DI or observability annotation without declaring the removal), `citation-check.sh` (a review asserting a file:line citation that overlaps nothing the session read — and this one records that its premise is evidenced rather than assumed: `--gate` had zero callers before the hook, so the blocking path had never run). Each line closes on the same condition, worded identically across the three so the marker reads as one convention: re-verify necessity at each major model generation, retire if it stops firing in real sessions across one. The convention is registered as a bullet under `docs/GOVERNANCE.md` § Conventions, so the marker is a governed surface rather than orphaned prose. It is a marker for a human pass, not a mechanism — nothing reads it, and no gate enforces it. Line 3 is deliberate: `scripts/generate_inventory.py`'s `get_desc_line` requires `# desc:` on line **2** exactly and inspects no other line, so the marker can neither displace it nor be mistaken for it.
